# 安全の仕組み

**日本語** | [English](safety.en.md)

Illustrator Studio MCP は、「直して」で終わらず、直ったところまで確かめます。変更前の計画と、変更後の結果確認を一つの流れにしています。

> **Public Beta 0.1.0-beta.2。** 試用版です。制作ファイルのコピーで試してください。Illustratorを前面に表示し、画面ロックを解除した状態が前提です。背面や画面ロック中は、操作が拒否されるか、理由の分かりにくい失敗になります。

## まず知っておきたいこと

- AIが示す対象と変更案を確認してから、適用を頼みます。書き込む直前にも、書類や対象が変わっていないか照合します。
- 実行後は、文字・位置・色など、その操作が検査する値をIllustratorから読み直します。見た目や入稿品質は、最後にあなたが画面で確認します。
- 同じ依頼の再送には、以前の実行記録を返します。現在の書類の状態が同じとは限りません。
- 応答が止まったら、変更できたか分からない状態として扱います。繰り返し実行せず、[復旧手順](runbook.md)に従ってください。
- バックアップは保存済みファイルと決められた構造の比較を確認します。すべての効果や外部リンク画像まで完全に復元できる保証ではありません。独立した制作原本も残してください。

## 続けて編集するとき

保存済みのファイルには、バックアップと作業中の占有を確認する「連続編集」（edit session、experimental）の仕組みがあります。39種類中36種類の変更操作が対象で、削除・画像埋め込み・ベクター取り込みは使えません。開始に必要なバックアップの上限が1,000オブジェクトなので、連続編集も実質1,000オブジェクトまでです（600オブジェクトでの実機1回からの外挿値で、1,000オブジェクトでは未測定）。作業中は、ほかの人やアプリから同じ書類を編集しないでください。外部の変更をすべて検出できるわけではありません。

## 既知の制約

長い書類の識別情報を持つ実行記録が読み戻せない問題と、一部グループが間欠的に読めなくなる問題は未解決です。記録の削除、別の依頼としての再実行、再起動で解決したとの推測はしないでください。[対応環境と検証範囲](compatibility.md)に確認済み・未確認の範囲を分けて掲載しています。

## 変更の流れ

オブジェクトやレイヤーなどを編集するツール（レシピ・一括操作を含む）は、共通の流れ `plan -> preflight -> apply -> verify -> rollback / reconcile` に従います。次のツールは別の形です。`apply: false` の計画も `command_id` も持たず、1 回の呼び出しの中で確認（preflight）と実行を続けて行います。ドキュメントの作成・別名保存・上書き保存・開く・閉じる、バックアップ、アウトライン書き出し、埋め込み画像の最適化（`apply` は持つが `command_id` は持たない）、edit session の開始・一覧・終了、および `illustrator_reconcile_backup`・`illustrator_reconcile_export` です。これらも、ドキュメントキーの照合と、実行後の読み直し・検証は行います。

```text
計画   apply: false。読み取りだけで、対象・変更内容・実行できない理由を返す
 ↓
照合   書き込む直前に、ドキュメントと対象が計画のときのままか確かめる
 ↓
実行   apply: true と command_id を付けて、1 回だけ適用する
 ↓
検証   Illustrator から結果を読み直し、計画と比べる
 ↓
復元   操作に応じた逆操作・回復手順で、検査対象の状態を照合する
       結果が不明なら、次の変更を止めて照合する
```

- 変更は、ドキュメントを明示したキー（`expected_document_key`）と、対象の識別子（Illustrator の `PageItem.uuid` など）に結び付けます。
- 照合は、変更と同じ Illustrator 呼び出しの中で行います。
- 呼び出しが返っただけでは成功とみなしません。読み直した結果が計画と一致したときだけ成功です。

## 制作中に気になることと、このサーバーの仕組み

| 制作中に気になること | このサーバーの仕組み |
| --- | --- |
| 別の文字や図形まで変わらない？ | ドキュメントと対象を特定し、変更直前にも状態を照合します |
| 実行する前に内容を見たい | まず変更計画を返します。適用を指定するまで書き込みません |
| 本当に指定どおりになった？ | Illustratorから結果を読み直し、操作に応じて文字・位置・色・順序などを検証します |
| 途中でうまくいかなかったら？ | 対応する復元手順を実行し、元に戻ったかも確認します。復元できない場合も明示します |
| 応答が止まった。もう一度頼んで大丈夫？ | 実行記録を保持し、結果が不明なら次の変更を止めます。同じ確定済みコマンドは重ねて実行しません |

実際の Illustrator で、作成・編集・結果の読み直し・復元・再送を操作ごとに検証しています。検証した環境と範囲は [操作別の実機確認](compatibility.md#操作別の実機確認) を参照してください。

## 検証が保証しないこと

- `verified` は、その操作が検査する値の一致を表します。全文書・全アピアランスの復元保証ではありません。文字スタイルの復元は割り当てを含む検証に修正しましたが、実際のツールで失敗を起こして復元まで通す実機確認は未完了です。
- この検証は、意図した変更が行われたかを確かめるものです。デザインの良し悪しや最終的な入稿判断は、あなたの目で仕上げてください。
- 操作ごとの復元は、制作ファイル全体のバックアップの代わりにはなりません。
- 再送で返る結果は過去の実行記録です。現在も同じ状態かを確認するには、最新のドキュメントキーで読み取り直します。

## 再送と、結果が不明なとき

- **同じ `command_id` は二度適用しません。** 確定済みのコマンドを再送すると、記録済みの結果（replay）を返します。変更内容が違う要求に同じ ID を使うと、書き込む前に拒否します。
- **タイムアウトは失敗ではなく「結果不明」です。** 結果が不明なコマンドが残っている間は、次の変更をすべて止めます。
- **照合してから次へ進みます。** `illustrator_reconcile` の `action=inspect` で状態を確認します。記録を放棄する `action=abandon` には、一致する `confirm_command_id` の指定が必要です。
- **結果を検証できないまま止まったコマンドは、最後の手段として明示的に解除できます。** `action=inspect` が `canReleaseUnverified: true` を返した時だけ、`action=release_unverified` に `command_id` と同じ値の `confirm_command_id` を付けて実行します。実行する前に Illustrator で、スクリプトが終わって応答していることと文書の状態を確かめてください（保存済みの文書は保存せずに閉じて開き直し、未保存の文書は目で確かめます）。解除しても文書の状態は検証されません。そのコマンドは二度と再送・再適用されないので、同じ変更は読み取りからやり直してください。記録は削除も圧縮もせず、証拠として残します。
- 結果が不明な記録は、自動では削除も圧縮もしません。状態保存フォルダを手作業で消さないでください。

止まったときの手順は [復旧手順](runbook.md#応答が戻らない結果が不明) にあります。

## 上書き保存・書き出し・バックアップ

- **上書き保存**（`illustrator_save_document`）には、`illustrator_create_backup` で作った検証済みバックアップの `backup_id` が必要です。バックアップとディスク上のファイルのハッシュが一致しない場合は、Illustrator に触れる前に拒否します。
- **バックアップ**（`illustrator_create_backup`）は、保存済みファイルを排他的にコピーし、復元テスト用のコピーを開いて構造を比較します。元のドキュメントとファイルは変更しません。バックアップは自動では削除しません。実質の上限は1,000オブジェクトです（600オブジェクトでの実機1回からの外挿値）。
- **別名保存と書き出し**（`illustrator_save_document_as`、`illustrator_export_outlined`、`illustrator_optimize_images`）は、まだ存在しないパスにだけ書きます。アウトライン化は書き出し用のコピーだけで行います。
- バックアップや書き出しの途中で結果が不明になった場合は、`illustrator_reconcile_backup` / `illustrator_reconcile_export` で解除するまで変更を止めます。
- **画像の埋め込み**（`illustrator_embed_image`）の対象は、RGB文書のレイヤー直下にあるリンクされたJPEG／PNGだけです。文書の中で元に戻せないため、削除と同じく clean な保存済み文書と検証済みバックアップの `backup_id`、plan が返した before / after の echo が必要です。埋め込みが実行された後に結果が不明になると Illustrator の lock が残ります。`illustrator_reconcile` の `action=release_unverified` で外した後、変更前のファイルはバックアップと同じなので、保存せずに閉じて開き直せば埋め込み前に戻ります（自動では行いません）。`embed()` 自体が拒否され、リンク画像が元のまま読み戻せた時だけ「変更なし」として確定します。
- **削除**（`illustrator_delete_objects`）は1回に1件です。検証済みバックアップの `backup_id` と、plan が示した target set hash と件数の echo が必要です。同じ呼び出しの中で元に戻す手段は無く、途中で結果が不明になると Illustrator の lock が残ります。この lock は abandon では外せません。Illustrator で文書を確認したうえで `illustrator_reconcile` の `action=release_unverified`（`confirm_command_id` つき）で外し、その後 `illustrator_reconcile_delete` で、保存せずに閉じて変更前のファイルを開き直せます。

## 利用上の注意

- ファイルとして保存済みのドキュメントは、変更前に保留中の変更を保存してください（`mutationProfile: saved_file`）。まだ一度も保存していない新規ドキュメントは壊れる既存ファイルがないため `unsaved_document` としてそのまま編集できます（バックアップは対象外）。`expected_document_key` には完全なキーか、`illustrator_get_context` が返す16桁の `keyShort` のどちらも使えます。作成したポイント文字のUUIDは次の保存で変わることがあります。
- 保存済みファイルを途中保存なしで続けて編集するときは `illustrator_open_edit_session` で占有を宣言します（検証済み backup が必要）。session 中は宣言済みの操作だけが dirty な文書を変更でき、外部の変更は次の変更か保存前の全体照合で拒否され、ファイルは書かれません。検出しない状態（アピアランス・配置画像の画素など）は利用者の責任範囲です。timeout のあとは session が suspended になります。まず結果不明のコマンドを照合し、文書状態を確認してから、session close → backup 契約での保存 → 新しい session という手順を検討します。sessionを閉じるだけで未解決コマンドのlockは解除されません。削除（`illustrator_delete_objects`）と画像の埋め込み（`illustrator_embed_image`）は、回復が変更前のファイルの開き直しで session の変更を捨てるため、session 中は使えません。
- 既定の接続先は `id:com.adobe.illustrator`（stable）です。`ILLUSTRATOR_APPLICATION` に名前形式を指定し、stable と Beta が同時に起動している場合は `application_ambiguous` で呼び出しを拒否します。`illustrator_get_context` / `illustrator_list_documents` は毎回 `application { bundleId, version, channel }` を返し、どのインスタンスが応答したかを確認できます。
- 文字編集は対応する書式に限定します。部分置換は範囲外の書式を保ちますが、手動ペアカーニング、U+200Dを含む内容、未測定の文字列境界などは拒否します。段落スタイル変更ツールは未対応です。
- 画像の差し替えではIllustratorがUUIDを置き換えるため、返却された新しいUUIDを使います。元画像と画素寸法が違う場合や元リンクが欠損している場合は拒否します。
- CMYK文書では、重なり順の変更は最前面（`front`）だけで、複合パスの作成は拒否します。
- オブジェクトが存在しないと判断できるのは、一覧の最終ページまで取得した場合だけです。印刷前検査も、未確認・取得打ち切りを含む状態で合格とはしません。

## 既知の停止・再送の制約

- 長いdocument keyは、実行記録の読み取り上限（4,096 bytes）を超えることがあります。入力側は16,384文字まで受け付けるため、書けた記録が読めない場合があります。文字数とUTF-8のbytes数は同じではなく、短いパスなら必ず安全という閾値も保証していません。読めない記録は拒否されます。別のcommand_idで再実行したり、記録を削除して回避しないでください。
- 一部のGroupItemが複数の読取経路で間欠的に無効になる問題は未解決です。読めない対象の読み飛ばし、自動retry、再起動による復元保証はしません。成功した後続測定も、元の失敗記録を置き換えません。
