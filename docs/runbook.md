# 困ったとき / Failure runbook

**日本語** | [English](runbook.en.md)

## 変更する前に止まった

対象が変わった、ロックされている、未対応の書式である、と拒否された場合は変更を強行しません。現在の対象を読み直し、新しい計画を確認します。古い計画をそのまま再利用しません。

## 応答が戻らない・結果が不明

1. 新しい編集、同じ変更の送り直し、自動retryを止めます。
2. 実行記録とテスト書類を保持します。記録やlockを削除して回避しません。
3. AIに「新しい変更をしないで、処理の状態を説明して」と依頼します。
4. 実行が継続中か、結果を照合できるかを確認します。reconcileは記録やlockを変更する場合があり、単なる読み取りではありません。対象の実行IDと操作内容を確認してから行います。
5. 根拠が揃わない場合は停止したまま管理者へ相談します。再起動を成功や修復の証拠と扱いません。

同じ実行IDの再送は過去の記録を返すことがあり、現在の書類が同じ状態という保証ではありません。長い文書識別情報では記録を読み戻せない既知の制約があります。

## 保存や復元に問題がある

バックアップは、その操作で検査した範囲の一致を確認するものです。すべての効果・外部リンク・入稿品質を保証しません。復元できたと推測せず、原稿とバックアップを保持して相談してください。

## 相談する

[Support](../SUPPORT.ja.md)へ、版、候補のchecksum、AIアプリとIllustratorの版、操作、確認できたこと、不明なことを伝えます。原稿、顧客情報、文書パス、実行記録の生データ、認証情報は貼り付けません。脆弱性は[Security](../SECURITY.ja.md)の非公開窓口へ。

この手順の実アプリごとの失敗経路の実測は未完です。手順書があることを復旧の成功証拠とは扱いません。
