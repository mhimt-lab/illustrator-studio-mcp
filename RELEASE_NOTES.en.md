# Public Beta 0.1.0-beta.7

[日本語](RELEASE_NOTES.md) | **English**

Published: 2026-11-23 JST (Asia/Tokyo).

An update from 0.1.0-beta.6. Illustrator 31.0.0 (2027) joins the checked versions. The default result of `illustrator_audit_typography` is now grouped (`grouped`), and large results are read in pages (`cursor`). It adds 15 tools, including `illustrator_set_text_composition` to write how existing text is set, `illustrator_plan_text_fit` to find tracking and horizontal scale that fit, `illustrator_plan_text_increment` to advance dates, weekdays and numbers by a rule, `illustrator_duplicate_artboard` to copy an artboard with its content, five tools for variables and datasets, inserting vertical space in a column, scaling a drawing to its real size, and replacing RGB-converted black with K100. SVG export, overwrite for exports, and barcode, QR Code, trim-mark and artboard-name changes inside edit sessions are also available. It is not a production-ready release.

**Prerequisite:** keep Illustrator in the foreground with the screen unlocked. In the background or while the screen is locked, most operations are refused.

#### Added

- `illustrator_set_text_composition`: writes how existing text is set. For a range inside one paragraph it writes proportional metrics, the kerning method (`none`, `auto`, `optical`, `metrics_roman_only`), tracking and horizontal scale. For paragraphs it writes the mojikumi set (7 built-in sets), kinsoku (Hard, Soft, Soft_v2, including "None"), the alignment of area text (7 values, including the justified ones) and leading (fixed pt or auto). With a list of ranges it writes the spacing (aki) on both sides of a character (em: auto, 0, 0.125, 0.25, 0.5, 0.75, 1). It also accepts area text with 1 to 20 columns. Attributes of characters, paragraphs and frames that it does not write are recorded before and compared after, and a change that would make the text no longer fully visible is undone. A paragraph whose attributes are all default, where Illustrator silently ignores writes of default values, is reset with the standard paragraph style and written back. A frame with an empty paragraph is refused because Illustrator does not let that paragraph's attributes be read. It was checked live on throwaway documents with point text and area text in Illustrator 30.8.2, and on a range that starts at character 0 in 31.0.0. Saved documents are not checked. It is experimental
- `illustrator_plan_text_fit` (read only): finds the tracking and horizontal scale at which one area-text frame shows its whole text, without changing the document. It copies the frame into a temporary document that is never saved, confirms that it displays like the original, applies candidates one at a time, and returns the first one that fits. The temporary document is closed without saving, and a result is returned only when the original document is read again and found unchanged. The default is 50 candidates (at most 100), and the caller decides the smallest horizontal scale it accepts. Not available on Windows
- `illustrator_plan_text_increment` (read only): returns a plan for replacements that advance dates, weekdays and numbers by a rule. The rules are to advance a date by N days, set a given date, or add N to a number. It returns the smallest range of changed characters, recomputes the weekday from the year and warns about a weekday that does not match, and keeps full-width and half-width characters, zero padding, brackets and wave dashes as they are. The dotted `M.D（曜）` form is supported. Japanese eras, English weekday names, dotted dates without a weekday and decimals are refused with a reason instead of guessed. The calls of `illustrator_replace_text_range` to use next are returned from back to front. It has not been checked live
- `illustrator_list_variables`, `illustrator_apply_dataset`, `illustrator_create_dataset`, `illustrator_update_dataset`, `illustrator_bind_variable`: work with variables and datasets. The read returns the variables, the objects bound to them, the datasets and the dataset shown last. Showing a dataset reads every bound object back, checks that only the attributes the variable kind decides have changed, and restores the previous values on a mismatch. Create adds a new dataset that captures the current values, and update overwrites an existing dataset with the current values (the values before the overwrite are returned in the result). `illustrator_bind_variable` binds an object to an existing or new variable, or unbinds it. Graph variables, text whose formatting differs by character, and colours that cannot be read, such as gradients, are refused. Reading, showing, creating, updating and binding were checked live in Illustrator 30.8.2. It is experimental
- `illustrator_duplicate_artboard`: copies an artboard with its content to a new artboard moved by a whole-number distance. It handles paths, compound paths, groups, text, placed images and raster images directly under a layer, in RGB and CMYK documents, including CMYK, spot and gradient fills and strokes. The plan returns the elements that cannot be copied and the elements already at the destination, with reasons, and apply reads the copied elements back and checks their attributes, positions and stacking order. Patterns, Lab colours and gradients on text are refused. It was checked live on an unsaved document in Illustrator 30.8.2. Saved documents are not checked. It is experimental
- `illustrator_insert_vertical_space`: in a tall image such as a cart, moves the elements below a break together to insert or close vertical space. One plan and one apply move the elements, stretch or shrink the guide rectangles that cross the break, and move the artboards and stretch their bottom edges. The plan returns the elements that cannot be moved and the artboards that are out of scope, with reasons, and apply reads the moved elements back and checks them. It targets RGB documents, saved, unsaved, or saved with unsaved changes. It was checked live in Illustrator 30.8.2. It is experimental
- `illustrator_activate_document`: brings a document that is not in front to the front so that later tools can work with it. It neither changes nor saves the document, and compares the selection, active layer and artboard, and view of all documents before and after. It was checked live only with Illustrator 30.8.2 in the foreground with the screen unlocked. macOS only, experimental
- `illustrator_measure_scale_reference` (read only): from two points or a path length and the real length (mm), returns the scale that fits a drawing to real size (`scale_percent`, six decimals), the spread between the references, and a hint on whether the drawing was read with mm as pt
- `illustrator_scale_artwork`: scales the elements directly under a layer around one point with a scale of up to six decimals (283.464567% for a drawing read with mm as pt). The plan lists the reasons it stops, and apply checks the position and size of every element against the prediction within 0.01 pt and the stroke width as requested (kept or scaled), and restores the elements on a mismatch. `verify_reference` measures a reference length before and after and returns the difference in mm. Artboards do not change. One call handles up to 700 elements
- `illustrator_normalize_stroke_widths`: for an explicit set of up to 256 paths, reads the distribution of stroke widths with counts per colour and layer, or plans and applies a mapping from intervals to seven stroke widths. Only the stroke width is written; the visible state is compared exactly and the change can be reversed. Siblings of a compound path must be included together and map to one width. It targets solid CMYK strokes in an unsaved CMYK document. A read, plan, apply and reversal of 256 paths were checked live in Illustrator 30.8.2
- `illustrator_replace_rgb_converted_black`: replaces the fill and stroke of the paths that the print preflight reports as `rgb_converted_black` with one CMYK value (K100 by default), up to 256 paths per plan and apply. The plan picks the writable paths and returns the count per value, what cannot be written and why, and what remains. Intended blacks, text, gradient stops and clipping paths are never touched. 256 paths in a document of 341 items were checked live in Illustrator 30.8.2
- SVG export: `illustrator_export` writes one artboard as SVG (an existing file is not overwritten). The XML, dimensions and geometry of the output are checked independently. Non-printing layers are refused at the plan. Documents with clipping, gradients or text are not supported. It was checked live in Illustrator 30.8.2
- Overwrite for exports: in `illustrator_export` (PNG, JPEG, SVG), `illustrator_export_pdf` and `illustrator_export_outlined` (AI, PDF), an explicit `overwrite` replaces an existing file. The old file is moved to a verified archive before the new one is published, and a stopped run is recovered with an explicit `restore_previous` or `finalize_publish`. PNG, SVG, PDF and outlined AI and PDF were checked live in Illustrator 30.8.2. Overwriting JPEG was not checked live. Exporting several artboards at once still cannot overwrite
- Operations inside edit sessions: the groups made by `illustrator_create_barcode`, `illustrator_create_qr_code` and `illustrator_create_trim_marks` can be mixed with other changes inside an edit session and saved once at the end. `name` and `renames` of `illustrator_update_artboard` also work in a session (`rect`, `rects`, `add`, `adds` and `active` are still refused). A QR Code above 1,500 rectangles, or one that would exceed the session's item limit, is refused before drawing
- `items` of `illustrator_embed_image`: embeds 1 to 16 linked JPEG or PNG images directly under a layer of one saved RGB document in one plan, one apply and one verified backup. Each image is at most 4,000,000 pixels, at most two exceed 960,000 pixels, and the total is at most 21,440,000 pixels. A failure after the first image is embedded is not undone and stops as an indeterminate result (close without saving and reopen)
- `names` of `illustrator_create_layer`: creates 2 to 32 layers in one plan and apply. The request, digest and result of a single `name` do not change. Creating 32 layers and the refusal at the limit of 256 layers directly under a parent were checked live in Illustrator 30.8.2. Windows refuses it until it is measured
- Short input form of `illustrator_create_batch`: `presets`, `targets` and `rows` shorten the input, and the `next_call` of a plan can refer to the steps by `steps_sha256`. The response is reduced to the reasons it stops, the baseline per layer, the UUIDs of created items, the status and failure, and the evidence of undoing. The limit of one call went from 16 to 64 steps. The plan estimates the size of the stored result and refuses a request above 80% of the limit with `result_too_large` before writing
- `illustrator_update_artboard`: `add`, `adds`, `name` and `renames` now work on a never-saved RGB document without the save, backup and edit-session detour (`rect`, `rects`, `active`, CMYK and a saved file with unsaved changes are still refused)
- `illustrator_preflight_print`: an optional `classify_blacks` tells CMYK blacks apart by kind (four-colour solid and RGB-converted black as errors, overprint-avoiding black and rich black as information). It adds `rich_black_min_text_pt` and `rich_black_min_stroke_pt` to warn about small text and thin lines in rich black, and reports a [Registration] colour inside the artwork as an error. An optional `maximum_total_ink_percent` (100 to 400) also checks the CMYK total ink. Without them the result does not change. Visible non-printing layers and the "Guides Preview for Trim View" layer are reported per layer with name, path and item count
- `illustrator_preflight_images`: an optional `target_ppi` returns, per placed image, the pixel size at that ppi, the ratio and the extent of the clipped source (`resizeSpec`). An optional `bleed_mm` (0 to 25, only together with `target_ppi`) also returns how far an image on an edge touching the artboard falls short of the edge plus bleed, and the mask shortfall
- `illustrator_plan_color_replacement`: a uniform, complete CMYK text fill in a CMYK document can now also be turned into a `set_text_style` step of `illustrator_mutate_batch` (for example fixing RGB-converted black text to K100)
- More targets for `illustrator_align_objects` and `illustrator_transform_object`: `illustrator_align_objects` also works with groups, linked images, embedded images and area text (horizontal and vertical) directly under a layer, in mixed kinds. `layout.as_group: true` aligns the moving targets as one block. `illustrator_transform_object` accepts `targets` (1 to 16) and moves, scales and rotates paths, groups, images and horizontal point text around the centre of the whole selection or of each target. Clipping groups use the centre of the mask, and scaling point text is checked by predicting the font size and leading
- More audits in `illustrator_audit_typography`: `jp_setting_profile_v1` (reports mismatches between the character and paragraph attributes listed in `setting_profile.expected`, or a named `preset` of the recommended settings, and the text), and `latin_body_v1` (rules for Latin body text such as quotes, dashes, ellipses, hyphens in number ranges, ASCII spaces between Japanese and Latin text, units split across lines and mid-word breaks; only the rules you specify are judged). `jp_paragraph_shape_v1` gains a rule for loose justified lines (`JP_LOOSE_LINE`, heuristic) that runs only when specified. A finding about a no-break split returns the plan of `illustrator_set_no_break` as `next_call`
- Character tsume in `illustrator_set_text_style` (`style.tsume`, 0 to 100): writes a range of single-line point text, and of point text with returns inside one paragraph item. Other characters, attributes, paragraphs and frames are compared in full before and after, and the change can be reversed
- Point text whose mojikumi is "None" (undefined) can now be handled by `illustrator_replace_text_range` (single line), `illustrator_replace_point_text`, `illustrator_replace_point_text_batch` and `illustrator_apply_character_style`. Point text with an empty paragraph, such as text that ends with a return, can also be written by `illustrator_replace_text_range` and `illustrator_set_text_style` when the range holds ordinary characters only (measured shapes only; replacements that include a separator and frames with adjacent empty items are refused)
- `compatibility` of `illustrator_save_document_as`: saves to a new path as an `.ai` compatible with `cc` (Illustrator CC) or `cs6` (CS6). The header of the written file is checked to be the requested version. A document saved in a compatible format is opened by Illustrator as a conversion, so reopening shows it as "unsaved" and the result returns `reopenedAsConverted: true` with a note. It was checked live in Illustrator 30.8.2
- `preferences` of `illustrator_get_context`: returns the four units, scaling of stroke weights and effects, preview bounds, pattern transform, the setting that treats unitless numbers as pt, and the corner setting, by reading only. A value that cannot be confirmed is `null`
- Hiding in the work copy of `illustrator_export`: an optional `exclude_non_printing_layers` hides non-printing layers only inside the work copy while exporting. The plan warns that layers set not to print show up in PNG, JPEG and previews (PDF drops them at the top level but not non-printing sublayers)
- Linked images in `illustrator_export`: documents with linked placed images (PSD, JPEG, PNG, including inside groups and clipping groups) can be exported. Before opening the work copy, the target of every link is read, and if even one cannot be read the export stops with the reason. Up to 100 links

#### Changed

- **The default result of `illustrator_audit_typography` is now grouped (`result_format: "grouped"`).** It states each rule description, frame and paragraph state once and lists ranges with the same evidence as `[start, end, line_index, position]`. Each finding can be turned back into the one-by-one form. The earlier one-by-one form can be chosen with `result_format: "findings"` (the shape of one finding is unchanged). When a scan limit (200 frames, 20,000 characters, 2,000 lines, 2,000 paragraphs, and 5,000 characters for policies that read character attributes), `max_findings`, or the new `max_response_bytes` (UTF-8 bytes of the result JSON, default 30,000, at most 80,000) is reached, it returns `next_cursor`, and the same input with `cursor` reads on (bound to the document, the input and the order of frames; refused if frames were added, removed or reordered). A frame that alone exceeds the limit of one read is listed in the result as `too_large` instead of silently stopping the scan. `scan_limit`, `line_cap`, `paragraph_cap`, `finding_limit` and `response_limit` in `incomplete` now mean "end of the page (with `next_cursor`)". `coverage` holds the values of that page, and `coverage.page` returns the position of the frames. A document with 300 frames and 12,000 characters was read to the end in pages and checked live in Illustrator 31.0.0
- Checked versions: the regression run passed live on Illustrator 31.0.0 (2027, stable), and 10 items are now checked operations on 31.0.0: updating artboards, deleting objects, embedding images, the clipping-mask family (create, release, compound path, pathfinder), importing vector artwork, editing path points, capturing previews, reading line height, optimizing images, and replacing a range of area text. The handling of other versions and other operations is unchanged. Part of the version check of the editing tools was fixed to 30.8.2, so other stable versions such as 31.0.0 now pass as unchecked versions under the same policy (the four step kinds of the batch, duplicating, replacing a range of area text, exporting SVG and work copies, and Illustrator's own font list). The result of a change carries `host_version`, and a saved file needs a verified `backup_id`. **Before updating:** because the policy table changed, a new version does not accept execution records made by the version before the update and treats them as a record mismatch (it neither deletes nor overwrites them). Resolve operations with an indeterminate result and open edit sessions in the earlier version first
- `tools/list` is about half the size (1,294,243 to 639,768 bytes). The results of editing tools publish the items that decide the next call (status, refusal code, document key, `next_call`) in full, and the evidence such as before/after snapshots and audits with a loose schema that accepts every value the full schema accepts. Tool descriptions are shortened to what is needed to choose a tool. The server still checks inputs and results against the full schema
- Precision of appearance values: the stroke width of an appearance (`illustrator_create_rectangle`, `illustrator_create_shape`, `illustrator_create_batch`, `illustrator_set_path_appearance`, `illustrator_mutate_batch`) is rounded at the plan to a multiple of 1/1024 pt and shown in `after`. The RGB of a path is shown rounded to an integer. `illustrator_set_path_appearance`, batches and recipes that only change a colour keep the existing stroke width exactly when `stroke.width` is omitted (a width is required to turn a stroke from off to on)
- Gradients in `illustrator_set_path_appearance`: the description now says `angle` follows Illustrator's orientation (y up: 0 = first stop on the left, 90 = bottom, -90 = from top to bottom), the opposite of the y-down coordinates of the create tools, and the plan returns `gradientDirection`. A path that already has a gradient can have only the gradient rotated to change the angle, when the request is otherwise the same as now. Scaling and rotating with `illustrator_transform_object` now also transforms the fill and stroke gradients of a path (linear and radial) and compares them after reading back (before, only the shape turned and the gradient kept its original direction)
- Free-form gradients in fills that read as gray 0: Illustrator's read cannot tell a free-form gradient fill from a real gray 0 (white). `illustrator_find_color_usages`, `illustrator_extract_design_tokens`, `illustrator_check_contrast`, `illustrator_preflight_print` and `illustrator_get_object` count them as before and add `possible_freeform_gradient_fills` and a note to the result. `illustrator_set_path_appearance` (including the same step in `illustrator_mutate_batch` and recipes) stops a request that changes a fill reading as gray 0 at the plan with `fill_may_be_freeform_gradient`, and `fill.confirm_gray0_fill_is_solid: true` lets it through once you have confirmed a real solid colour
- `illustrator_save_document` now saves without losing the embedded ICC profile, PDF compatibility and compression (it uses Illustrator's menu save). `attributes` in the result reports whether the ICC profile, PDF compatibility and compression read from the files before and after are `preserved`, `changed` or `unknown` (an unreadable attribute is `unknown`, and `verified: true` only when all are `preserved`). A save that changed attributes returns `saved_attributes_changed`
- A file or folder whose path contains `%` followed by two hex digits (`%20`, `%2F`, `%E3%81%82`) is refused with a reason (`path_contains_percent`), because Illustrator reads the path as a URI and it would become other characters or another folder. `50%off` and a lone `%` are accepted
- `illustrator_set_text_style` now records and reports the actual attributes and the change (position, column, before and after) of the return (CR, U+0003) right after the end of the range. Before, it changed without a record. A shape where the attributes of all characters and of the separator cannot be recorded or read is refused before writing. When `illustrator_replace_text_range` refuses point text that has manual pair kerning, tabs or frame tags, it names the cause and the frame in the message and adds `next_steps` (`custom_script`)
- The single line of `illustrator_replace_text_range` now also handles point text whose attributes differ from the fixed values, such as a different baseline shift per character, or kinsoku and auto-leading amounts that differ from the defaults, by recording every attribute before the change and comparing after (it restores if even one thing outside the range changes). A document with centre alignment and mixed baseline shifts was checked live in Illustrator 30.8.2
- `set_text_style` in `illustrator_mutate_batch` (16 steps, 192 characters) stopped at the plan with `result_too_large`. It now carries consecutive characters with the same attributes as one run (`runs`). Every character is still read, compared and verified
- The plan of `illustrator_create_point_text`, `illustrator_create_shape` and `illustrator_create_batch` is now returned, with the reason `layer_item_capacity_exceeded`, even for a layer with 129 or more items directly under it. The plan reads only the first 128 UUIDs, so the time to read and the size of the result do not grow with the number of items in the layer
- Checking the result of `illustrator_find_fonts` is faster (a search over 5,000 fonts that took about 13 seconds now takes a few milliseconds per page). `illustrator_preflight_print` took about 10 seconds for 500 items and now takes about 4 seconds. Items are read in layer-tree order, so findings follow the layer tree. When the host deadline (24 seconds) is reached, it stops with `READ_SCAN_DEADLINE` instead of returning a result
- The message of an indeterminate result now includes the `reason_code` and position of the first verification issue (and the count of the rest). Values that could contain document text are not shown
- The description of `illustrator_create_qr_code` carries the QR Code registered-trademark notice. It is not put in results, errors or object names

#### Fixed

- Writing the kerning method of `illustrator_set_text_composition` from character 0 was undone with a verification mismatch. Character 0 has no character on its left and follows its own method, so when a range starts at character 0 the read of the manual kerning amount of character 0 is treated as derived from the method (measured in Illustrator 31.0.0). When character 0 has an actual manual amount, it is still refused with `composition_manual_kerning`
- In `illustrator_create_rectangle` and `illustrator_create_shape` (including the same step of `illustrator_create_batch`), the initial appearance `stroke: { kind: "none" }` is no longer undone by verification in a document whose default stroke width is not 1. A request in `illustrator_set_path_appearance` (including the same step in batches and recipes) that turns a stroke whose width is not 1 to "none" was also undone by verification, and is fixed. The width of a stroke that is off is excluded from the comparison (the kind of stroke, the width and colour of a solid stroke, the fill and the opacity are still compared exactly)
- Decimal values of an appearance that differed between plan and apply and made apply always refused are fixed (Illustrator stores stroke width as a 32-bit float and path RGB as integers). Apply was always refused when the echo of a number that Illustrator returned with 15 significant digits was compared with `===`; this is fixed in `illustrator_duplicate_artboard`, `illustrator_update_artboard`, `illustrator_set_path_appearance`, `set_object_state` of `illustrator_mutate_batch`, and `illustrator_replace_area_text_range`
- On an unchecked stable Illustrator, the temporary path of an unsaved document was mistaken for a saved file and a backup was demanded. This is fixed
- `illustrator_relink_image` lost the `note` (the memo of the Attributes panel), `uRL` and user tags of the item rebuilt by the replacement. It now records them before the replacement and restores them, and is not verified if they cannot be restored
- `illustrator_place_image` put an image on a hidden active layer and left the undo marked verified. It now makes the target layer active before placing and returns to the original active layer afterwards (not verified if it cannot). `illustrator_relink_image` reads back that the active layer and selection are the same after the replacement
- `illustrator_find_color_usages` did not find colours stored in single precision (C93 read as 93.0000007) even when searching CMYK with tolerance 0
- `illustrator_list_selection` failed while a range was selected with the Type tool (`items` is empty and `text_selection` is returned). `illustrator_create_clipping_mask` refuses a selection made while editing text with `text_editing_selection`
- A read that never started left its lock behind after its owner vanished, making every tool unusable. The next call now releases a lock that has no owner, never started, and is older than the read timeout limit plus 60 seconds. Checking and removing a lock is now one operation, so a simultaneous release or automatic recovery cannot remove another call's lock. When backup, export or save-as stopped after creating the lock and before creating the command and could not be released, it can now be released by passing the session id explicitly to `illustrator_reconcile_backup`, `illustrator_reconcile_export` or `illustrator_reconcile_save_as`
- Duplicating an artboard that contains groups was refused by verification, and the rollback could not be confirmed, because Illustrator's item count reads late (it answers short after a group is duplicated). `illustrator_update_artboard`, `set_object_state` of `illustrator_mutate_batch` and `illustrator_set_stroke_style` now use an enumeration, to check that a document holds "only ordinary paths directly under layers", that does not read stale right after a group is duplicated
- The plan of `illustrator_run_m6_appearance_preview_recipe` refused `gradientDirection` and `gradientRotation`, which were added to `illustrator_set_path_appearance`, with `Unrecognized keys`. This is fixed
- In a new Claude Desktop, arguments could not be passed to the change tools that work in two steps, plan and apply (56 tools such as `illustrator_create_rectangle`), and the call failed with an input error. This is fixed. The input definition of each tool is now published as one object that has the list of arguments, merging the plan form and the apply form. Arguments used only by apply (such as `command_id`) start their description with "Apply only.". A combination of arguments that fits neither plan nor apply is still refused by the server as before

#### Known limitations

- `illustrator_set_text_composition`, `illustrator_duplicate_artboard`, `illustrator_insert_vertical_space`, `illustrator_activate_document` and the five variable and dataset tools are experimental. They were checked only on throwaway documents made in Illustrator 30.8.2 (31.0.0 for the character 0 case of `illustrator_set_text_composition`); saved documents are not checked. Inputs outside the supported range of `illustrator_plan_text_increment` and `illustrator_plan_text_fit` are refused with a reason instead of guessed
- `illustrator_scale_artwork` handles up to 700 elements per call. SVG export in `illustrator_export` does not support documents with clipping, gradients or text
- When `illustrator_duplicate_artboard` is applied to a document that contains compound paths and Illustrator's item count reads late, both the verification and the check after the rollback are refused, and the result is indeterminate (`rollback_indeterminate`) because the final state cannot be proved. Read the original document and the copy again to check them
- Only 10 items were checked on Illustrator 31.0.0. The restore after a failed spot-colour creation, exporting an exact pixel size, exporting SVG and work copies, and duplicating inside groups and batches are handled as unchecked versions. 31.0.0 is not checked on Windows
- Adobe Fonts can be written only when they are in the font list read before any document was opened. After a server or Illustrator restart, and for fonts added after the list was read, read it again with every document closed. Using Adobe Fonts with `illustrator_replace_font` has not been checked live. Text creation and the character style tools still check fonts inside Illustrator only
- `illustrator_replace_text_range` and `illustrator_set_text_style` stop with `result_too_large` when one frame exceeds about 200 characters with short font information (about 180 with returns or forced line breaks), because of the size of the execution record. Split the range or the frame
- The decode checks of `illustrator_create_barcode` and `illustrator_create_qr_code` need zbarimg, which is not bundled; without it the check is `not_run`. Geometry and decode checks are not GS1 certification or a guarantee of scanning in print, and barcode placement on the case is not checked. Check the code under your final print conditions (method, paper, ink, reader)
- `illustrator_set_stroke_style` supports only the one measured shape: an open three-point straight path in a never-saved, one-layer CMYK document
- `illustrator_replace_area_text_range` is checked on Illustrator 30.8.2 only with one justified paragraph whose last line is aligned left, and on 31.0.0 only with one test document
- `illustrator_render_artboards` does not bring Illustrator to the front. Bringing Illustrator to the front in `illustrator_capture_preview` and `illustrator_extract_text` is not done while the screen is locked and is not supported for a minimized Illustrator or one on another desktop (Space)
- In edit sessions above 3,000 objects, an outside attribute change made after its scan and before the save can be missed. Opening and saving take several minutes or more
- Changes continued as `dirty_file` do not detect changes outside the named targets
- Changes an AI app makes with its own script after a `custom_script` refusal are outside this server's plan, apply and read-back checks. Check the result with the read tools
- Changes on unchecked versions are checked by the before/after comparison, but have no live check on that version
- The layer-state steps of `illustrator_mutate_batch` and the tracking and scale text style steps have not yet been checked live through the published tools
- `pdfx` in `illustrator_export_pdf` checks only that PDF/X information was written. Conformance is not validated
- The short-line rules of `illustrator_audit_typography` are heuristic, and the loose-line rule (`JP_LOOSE_LINE`) runs only when specified and was checked live with one setting. The rules with which it finds prohibited line breaks are verified by automated tests; live checks covered only that documents with Hard kinsoku get zero line-start and line-end findings. Ruby, warichu and forced line breaks are not judged
- `illustrator_create_trim_marks` has no Japanese or Roman default dimensions. Give every dimension
- `illustrator_optimize_images` could stop at render verification on large images (800×800 pt at the origin) in Illustrator 30.8.2 (not reproduced on 31.0.0)
- `illustrator_replace_font` does not support composite fonts. In a saved document, each chunk needs a backup and a save. If the replacement font lacks the glyphs, verification fails and the change is reverted
- Moving text frames directly on a layer has not been checked on CMYK documents
- In `illustrator_mutate_batch`, the appearance, text-replacement and text-style steps do not return `next_steps` when they stop at a locked or hidden parent group (nothing is written)
- Writing the `illustrator_run_m6_appearance_preview_recipe` preview to a sync folder such as iCloud can be refused as changed even when the contents are the same. Write it outside sync folders
- Appearance at creation does not support spot colors or gradients. Use `illustrator_set_path_appearance` after creating
- Exporting a 4000×3000 px JPEG temporarily used about 570 MiB of Node.js memory to check its size (one measurement)
- Streamable HTTP is limited to automated tests and client connection checks. There is no record of operating Illustrator over HTTP
- In CMYK documents, compound path creation is not supported
- Group reads have a known intermittent issue where the target cannot be referenced. The cause is unresolved. When it happens, the operation stops on the safe side (fail closed), and results that cannot be confirmed are treated as indeterminate
- Execution records with long document identity information may not be readable back
- Existing stroked text cannot be edited
- Windows support is still in preparation; the published package is Mac only
- The Desktop extension is not signed. Check the author and version in the install dialog
- Always include `@beta` with npm. An install without a tag uses `latest`, which may not be this version
