# Public Beta 0.1.0-beta.6

[日本語](RELEASE_NOTES.md) | **English**

Published: 2026-10-14 JST (Asia/Tokyo).

An update from 0.1.0-beta.5. It adds JAN (EAN-13 and EAN-8), ITF-14 and QR Code symbols drawn as editable vectors, a letter-spacing analysis for headlines and logotypes, rendering and comparing artboards without changing the document, extracting all text, range replacement in one-paragraph area text, stroke dashes, caps and corners, and scaling some anchors of a path. Exports can cover several artboards at once or an exact pixel size, PDF export can request PDF/X, text inside groups can be edited, the typography audit gains justification and paragraph-shape checks, and backups, edit sessions, reads and changes work on documents of about 20,000 objects. Editing tools now run on unchecked stable Illustrator versions without asking for consent. It is not a production-ready release.

**Prerequisite:** keep Illustrator in the foreground with the screen unlocked. In the background or while the screen is locked, most operations are refused.

#### Added

- `illustrator_create_barcode`: draws an EAN-13 (JAN standard), EAN-8 (JAN short) or ITF-14 barcode with its digits as editable vectors, in one group on the layer you name. Bars are fill-only black rectangles (CMYK K100 or RGB 0,0,0), with or without a white background. The digits are outlines of the bundled OCR-B font, so no font needs to be installed. The check digit is validated by default and calculated only with `check_digit: "calculate"`; numbers are never assigned. Size is a magnification of 0.8–2.0 or `x_dimension_mm` 0.264–0.66 for EAN, and `x_dimension_mm` 0.635–1.016 (default 1.016) for ITF-14. ITF-14 requires a bearer bar (`bearer_bar`: `plate` or `non_plate`), and a 13-digit GTIN gets a leading 0 only with `normalize_gtin13: "prefix_zero"`. The planned bars, and after the apply a render of a copy in a throwaway document, are decoded with zbarimg and compared; a mismatch is never returned as a success. Checked live on Illustrator 30.8.2 with EAN-13 (magnification 1.0), EAN-8 (0.8) and ITF-14. Not available in an edit session
- `illustrator_create_qr_code`: draws a QR Code (Model 2, versions 1–40, error correction L/M/Q/H) from text such as a URL or Japanese (UTF-8) as editable vectors. The dark modules, merged into one rectangle per horizontal run, form one compound path, grouped with an optional white rectangle that carries the quiet zone (at least 4 modules). The foreground is black only (CMYK K100 or RGB 0,0,0). `size_pt` is the side of the whole square including the quiet zone, and the plan returns the version, module count, rectangle count and the size of one module. The planned rectangles, and after the apply a render of a copy in a throwaway document, are decoded with zbarimg and compared with the content; a mismatch is never returned as a success. Live, a version 40 / H symbol of 7,842 rectangles was created and checked in 3.95 s. Styling, logos, other colors and GS1 conformance are not covered. Not available in an edit session
- `illustrator_analyze_display_spacing` (read-only): measures the letter spacing of one headline or logotype frame: one line of horizontal point or area text, up to 64 characters, one font size, Latin or Japanese. The default `measure: "outline"` copies the frame into an unsaved scratch document, outlines it there, and returns for each pair of adjacent letters the box gap, the smallest ink gap, the white between them, collisions, the deviation from the frame median, and a suggested kerning change (1/1000 em) toward the median or `target_white_em`. The suggestions are heuristic; judge them at the final size and medium. The scratch document is active for about half a second and is closed without saving; Illustrator must be in the foreground with the screen unlocked. `"state_only"` reads only the kerning method, manual kerning, proportional metrics, tsume, aki and tracking, and opens nothing. `include_preview` adds a 288 ppi PNG of the outlined copy. Path, vertical, threaded, locked or hidden, transformed and multi-line frames are refused. The document key, saved state, counts, selection and view are compared before and after, and any change is an error. 13 checks passed live on 30.8.2
- `illustrator_render_artboards` (read-only): renders each artboard to PNG (72 or 144 ppi) without changing the document. `source: "current"` renders the open document while it has unsaved changes (`saved=false`), and `"file"` renders the saved file from a private copy. With `compare_to` (an earlier render), it returns the changed pixels, their bounding box and a difference image for each artboard. One call covers up to 100 artboards and 60 megapixels. Renders can be referred to while the server runs; older ones are cleaned up beyond 24 hours, 20 sets or 2 GB (`cleanup` in the result reports the counts). Needs the foreground and an unlocked screen; it does not bring Illustrator to the front
- `illustrator_extract_text` (does not change the document): returns the text of every text frame by artboard, with paragraphs (returns) and lines (forced line breaks) separated and trailing breaks flagged. One call covers up to 5,000 frames and 400,000 characters; continue from `truncated.nextStartIndex`. With `activate_if_needed: true`, it brings the configured Illustrator to the front when the screen is not locked, then reads (no document is selected or saved)
- `illustrator_replace_area_text_range`: on Illustrator 30.8.2, replaces a range in horizontal, unthreaded area text directly on a layer with one paragraph and one column (1–5,000 characters, all visible to begin with). Only justified text with the last line aligned left is checked; other alignments are refused. The replacement may be empty and cannot contain line breaks. Mixed formatting outside the range is kept, and line wrapping is read from what Illustrator composed, not predicted. Overflow or a mismatch is reverted. Text with surrogate pairs (such as emoji and some kanji), manual kerning, tabs or lists, and mixed formatting inside the range are refused
- `illustrator_set_stroke_style`: sets dashes, dash offset, cap, join and miter limit together (solid, dashed, round dots and so on). Only these five are written; fill, stroke color, stroke width, opacity, geometry and every other object are compared before and after, and any change is rolled back. The target is an open three-point straight path with CMYK fill and stroke in a never-saved, one-layer CMYK document, with Illustrator in the foreground and the screen unlocked. Other documents and shapes are refused as unmeasured. Not available in an edit session
- `illustrator_transform_path_anchors`: scales chosen anchors of one path together with their handles, by separate horizontal and vertical factors (0.25–4), about a given point or one of the anchors. Anchors are chosen by index, y range or x range. Point types, point count and the closed state never change. The target is a path directly on a layer (up to 256 points) with RGB paint, or in a CMYK document CMYK fill and stroke, a spot fill or `NEGATIVE` polarity. The apply is checked by read-back, and on failure every written point is restored
- Several artboards in `illustrator_export`: `output_dir` (an existing folder) with `artboard_indexes` (up to 32) or `all_artboards: true` exports several artboards in one plan and one apply. Files are named `<artboard name>.png` or `.jpg`, and names are never converted. An unusable or repeated name (ignoring case and Unicode normalization) or an existing file stops the whole plan with a reason for each artboard. Every file is checked before any is published, and if one fails, only the files this export placed are removed. Live, 8 real artboards (1025×3840 px JPEG) were exported in 5.4 s
- Exact pixel size in `illustrator_export`: for one artboard, `width_px` or `height_px` can replace `scale`. The aspect ratio is kept; both sides must be whole pixels, at most 4000 px per side and 12,000,000 px in total, and the file is published only when its decoded size equals the plan exactly. On stable Illustrator 30.8.x (measured on 30.8.2), JPEG and PNG (transparent or opaque) can be written at 25–400% (11 sample points measured per format). The artboard size must be whole points, and it is not available for several artboards. The foreground and unlocked screen are checked once before the first Illustrator call; Illustrator is not brought to the front automatically
- `pdfx` in `illustrator_export_pdf`: requests a PDF/X standard explicitly (`x3_2002`, `x3_2003` or `x4`). `output_condition` is accepted with `x4` only. X-1a is refused because Illustrator was measured to ignore it silently. The export is also refused when a document font cannot be confirmed on this machine (a missing font is replaced silently and no PDF/X information is written). The written file must carry the PDF/X version (Info and XMP) and an OutputIntent, but conformance is not validated (`pdfx.conformance` is always `not_validated`). PDF/X presets remain unavailable
- Document bleed and editability in `illustrator_export_pdf`: `bleed: {mode: "document", expected_mm: 3}` leaves bleed to the preset's "Use Document Bleed Settings" and publishes only when every page has a BleedBox of 3 mm on each side (0.01 pt tolerance). For explicit whole-point bleed, use a preset with that setting off (with it on, the document's values are used and the check stops the export). `preserve_editability` writes "Preserve Illustrator Editing Capabilities" only when given and returns the value read back in `options.preserveEditability`: `false` for sharing and mail (measured: a one-page PDF fell from 16.4 MB to 387 KB), `true` to reopen and edit in Illustrator; omitted, the preset's value is kept. When trim or registration marks are requested and the document already has strokes in the Registration color (such as trim marks from `illustrator_create_trim_marks`), the plan warns (it scans the first 5,000 paths and never blocks)
- Two new audits in `illustrator_audit_typography`: `policy` adds `jp_justify_body_v1` (justification and spacing) and `jp_paragraph_shape_v1` (paragraph shape). `jp_justify_body_v1` reads each paragraph's alignment and its word spacing, letter spacing and glyph scaling (minimum, desired, maximum), and runs only the rules given in `justify_body`: the last-line treatment of justified text (`JP_JUSTIFY_LAST_LINE`), values outside a range (`JP_SPACING_RANGE`) and a short last line (`JP_SHORT_LAST_LINE`). `jp_paragraph_shape_v1` runs only the rules given in `paragraph_shape`: a line after an automatic break that starts with a few characters and then punctuation of the classes you list (`JP_SHORT_LINE_HEAD`), and a short last line in any paragraph of two or more lines. No thresholds are assumed; the result returns the distribution over the audited paragraphs and the new-document defaults as reference. The document is not changed. **Result shape changed:** the result gains `policies` and `justify_body`, and `policy` is `null` when `jp_line_break_v1` is not requested
- Point text inside groups: `illustrator_replace_text_range`, `illustrator_replace_point_text` (including `illustrator_replace_point_text_batch`), `illustrator_set_text_style` and the matching `illustrator_mutate_batch` steps edit point text inside groups (nested groups, and clip groups whose first child is the clipping path) without ungrouping or moving anything. The plan pins the state of every ancestor group (UUID, lock, visibility, opacity, blending mode, clipping and child order), and a change stops before writing. Locked or hidden ancestor groups, more than 32 nested groups and groups of more than 1,024 children are refused with the group named. Applying a character style is not included
- Point text with several paragraphs: `illustrator_replace_text_range` and `illustrator_set_text_style` accept point text of up to 32 lines separated by returns (paragraphs) or forced line breaks. The range stays inside one line, and one character can be replaced by one return or forced line break to split it. Edits that leave an empty line, and deleting or changing a separator, are refused. Character, paragraph and frame attributes are compared before and after. **Reported numbers changed:** these two tools also report the numbers of one-line text as five-decimal values
- Character alignment and leading reference in `illustrator_set_text_style`: `style.alignment` (`center` or `roman_baseline`) sets the character alignment of one-line text whose characters use the standard character style. `paragraph_style.leading_type` (`top_to_top` or `bottom_to_bottom`) sets the leading reference of one whole paragraph of point text with two or more paragraphs directly on a layer (when its characters share every attribute, use the standard character and paragraph styles and are aligned left). Neither can be combined with another attribute. `illustrator_get_object` returns `alignment` per style run and `leadingType` per paragraph
- `illustrator_set_no_break` on area text: also works on horizontal, unthreaded area text directly on a layer with one paragraph (all text visible, aligned left or justified with the last line left). The plan and result return the lines Illustrator composed before and after. If no-break makes the text overflow its frame, verification fails and the change is reverted. **Result shape changed:** for point text too, the per-character `characters` of the snapshots are now `runs` of equal attributes (result schema version 3)
- `style.leading` in `illustrator_create_area_text`: sets leading as a number (points, up to five decimals), written with auto leading off on every character; the result returns the actual value read back. One paragraph only for now (a line break is refused). Omitted, auto leading is used as before
- `illustrator_align_objects`: also aligns horizontal point text directly on a layer (2–16, not mixed with paths), and `distribute` gains `spacing: "gaps"` for equal edge-to-edge gaps. The two outermost targets do not move. When the outer width is smaller than the targets' total, it stops with `negative_gap` before writing. Only 180° rotation has been checked
- Placement in `illustrator_create_shape`: creates a shape directly above or below a reference path (by UUID) that is directly on the layer, unlocked and visible. Omitted, the shape is created at the front as before
- `activate_if_needed` in `illustrator_capture_preview`: with `true`, when Illustrator is not in front and the screen is not locked, it brings the configured Illustrator to the front before capturing (it does not launch Illustrator, select or save a document, or restore the previous focus), and checks again that it is in front. **Refusal codes changed:** `PREVIEW_UNSUPPORTED_HOST_PROFILE` is split into `PREVIEW_ILLUSTRATOR_NOT_FRONTMOST`, `PREVIEW_SCREEN_LOCKED` and `PREVIEW_HOST_PROFILE_UNKNOWN`, and `PREVIEW_ACTIVATION_FAILED` is added. Because they can change the focus, this tool and `illustrator_extract_text` are not annotated as read-only (`readOnlyHint`)
- `query` in `illustrator_find_fonts`: partial match on PostScript name, family or style (ASCII, 1–64 characters), 50 per page. Measured: about 1.3 s per call with 4,939 fonts installed. It cannot be combined with `post_script_names`
- Batches and artwork in `illustrator_update_artboard`: the arrays `renames`, `rects` and `adds` rename, move or resize, and add several artboards in one plan and one apply (1–256 entries, up to 256 boards). Moves, resizes and adds also work in documents with artwork beyond paths, such as text and groups, pinned by the UUIDs of every object and the top-level bounds (measured up to 20,778 objects and 3 s per scan; an apply can take about 9 s to respond). Adding a board that overlaps or touches an existing one is stopped in the plan with the reason and index. Documents with sublayers, guides or path text are out of scope. `pixel` is accepted only for a single move, resize or add
- New `illustrator_mutate_batch` steps: moving to a layer (`move_object_to_layer`), applying a character style (`apply_character_style`) and layer state (name, visible, locked), each in exactly 2 steps, and object state (`set_object_state`: name, opacity, hidden, locked) in 2–3 steps. Text style steps gain tracking (whole numbers only, since Illustrator stores fractional tracking as a whole number), horizontal scale and vertical scale. Each accepts only the small setups measured live (counts of root layers and targets, color mode, font and so on) and stops anything else before writing. Object-state steps run on Illustrator 30.8.2 only
- Duplicating inside groups with `illustrator_duplicate_object`: paths in 1–3 plain groups (single-layer RGB documents), text (narrow conditions such as short ASCII text) and images (unscaled linked PNG or embedded RGB) inside groups, and, in single-layer CMYK documents, CMYK-filled paths in two groups and paths directly on a layer filled with an ordinary CMYK-based spot color. The siblings, their order and the spot definitions must be identical before and after, and on failure only its own copy is removed. RGB- or Lab-based spots, Registration, gradients, patterns and spot strokes are refused
- Group moves in `illustrator_transform_object`: groups holding embedded images (8-bit RGB or CMYK) and clip groups directly on a layer masked by a frontmost closed path can now be translated. In CMYK documents, within a one-level group holding point text, a two-point straight line and a rectangle, the text and the line can be moved inside the group (also in `illustrator_mutate_batch`). Group scaling and rotation, nested clips and compound-path masks are not supported
- CMYK documents in `illustrator_embed_image`: embeds flat 8-bit PSD (RGB or CMYK) and CMYK TIFF files that carry an ICC profile into a CMYK document. The one-child group Illustrator creates is removed, leaving a CMYK embedded image directly on the layer. Files without an ICC profile, PSD with a layer or channel count other than measured, RGB TIFF, 16-bit and multi-page files, and rotated, skewed or non-uniformly scaled placements are refused in the plan. A clipping mask for such an embedded image cannot be made yet
- CMYK documents in `illustrator_set_stacking_order`: paths with CMYK fill and stroke, a spot fill, one tag or `NEGATIVE` polarity can now use every method (front, back, forward and backward) in CMYK documents (16 checks passed live on a copy of a production file). A refusal names the property that caused it
- Continuing unsaved changes (`mutationProfile: dirty_file`): a saved file with unsaved changes is no longer refused for that reason alone. `illustrator_set_text_style`, `illustrator_replace_point_text`, `illustrator_replace_text_range`, `illustrator_transform_object` and `illustrator_set_path_appearance` continue without an edit session, checked by comparing the named targets before and after. Changes outside those targets are not detected (the result's `document_admission` says so). Other operations are refused as before. After a change that was released without verification or could not be rolled back, this way of continuing and saving through this server are refused until the document is back to an unchanged state. For several changes that the user checks and saves, the guidance is to open an edit session before the first change; after `illustrator_close_edit_session`, the user can save in Illustrator (Cmd+S)
- `setup` command: `npx -y illustrator-studio-mcp@beta setup --client claude-code` (or `--client codex`) prints the registration command pinned to the version it runs from. It does not read or write the AI app's settings and does not start the AI app, the MCP server or Illustrator. With `--current` and `--previous`, it also prints update and rollback commands; `--json` gives structured output

#### Changed

- **Before updating:** resolve indeterminate operations, open edit sessions, and stopped exports and save-as runs with the version you are updating from. Because version checks were corrected, the 10 operations that check the version refuse execution records made by an earlier version as a record mismatch (nothing is deleted or overwritten). Going back to an older version is not supported while an export, save-as or edit session on a non-ASCII path (such as Japanese) is unresolved. Right after an update, continuing unsaved changes (`dirty_file`) and saves can be refused once because earlier records cannot be verified by the new version (save or close the open saved documents and read `illustrator_list_documents` to clear it)
- Unchecked versions: consent is no longer asked. On an unchecked stable Illustrator version (including another major or minor version), the editing tools that check the version (such as embedding images, deleting, editing path points and importing SVG) plan and apply without `accept_unmeasured_host_version` (a value sent by an older AI app is accepted and ignored). `host_version` in the plan and result says the version is unmeasured, and the change is checked by the before/after comparison. On an unmeasured version, an operation that changes a saved file requires a verified backup (`backup_id`) before the apply; without it, `HOST_VERSION_BACKUP_REQUIRED` stops with nothing changed. Blocked or unreadable versions and non-stable channels (such as Beta) are still refused, and exact-pixel export refuses minor versions other than 30.8
- Guidance for refusals: the next steps now depend on the kind of refusal. A refusal because a feature is missing, unmeasured or outside the measured scope carries `custom_script` in `next_steps.actions`, and the AI app may then go ahead with its own script outside this server without asking first (say what it will change, make an `illustrator_create_backup` first for a saved document, check and report the result with the read tools, and read the document key again). It is not given after an indeterminate result, an unresolved lock, a mismatched target or an environment state such as a locked screen or Illustrator not in front; resolve those through this server and retry. Limits still return `narrow_scope`, and locked or hidden targets `unlock_target` or `show_target`. Within that scope, this replaces the beta.5 rule in the server instructions not to make the same change through a custom script. This server has no tool that runs arbitrary scripts
- `illustrator_create_backup`: documents above 1,000 objects are verified by reading every record twice, requiring both passes to match, and comparing them, up to 20,778 objects on macOS (37.8 s on a 20,778-object production file). A larger document stops with `document_too_large`, its object count, the limit and a workaround
- Edit session limits: one full scan now admits up to 3,000 objects (was 2,000) with a 60 s deadline (was 15 s). Above 3,000, a document opens in chunks (`scan_continuation`) up to 20,779 objects. Saving such a document has a window (measured at about 12 minutes) in which an outside attribute change made after its chunk was scanned can be missed, so ask the user before passing `accept_chunked_scan_window: true`. On a copy of a production file of about 20,000 objects, opening took about 6 minutes and saving about 12.5 minutes. Documents with embedded (not linked) images can now be opened too (outside changes to position, size, name, opacity and similar are detected before saving; pixel and profile changes are not)
- `illustrator_save_document`: when the full scan of an edit session does not finish in time, the session is no longer suspended; nothing is written, `edit_session_scan_incomplete` is returned and the session stays open. Run it again, and do not restart Illustrator before the changes are saved
- `illustrator_list_objects` and `illustrator_get_object` no longer slow down with the square of the document size (on 20,778 objects, a list call or an absence check takes 0.5–1.7 s). Editing tools also find their target directly: on the same document, an `illustrator_set_object_state` plan went from 18.8 s to about 0.37 s, and an apply that used to hit the 30 s timeout now takes about 0.48 s. **Listing order and cursors changed:** the list follows the layer tree (a group's children right after it), and cursors are version 2; a version 1 cursor is refused as stale, so list again from the start
- Smaller `illustrator_mutate_batch` responses: each step returns the request, blockers, the values that change (`changes`) and the SHA-256 of the before and after snapshots, and an apply returns `postconditionSha256` and any difference from the prediction (`observed`) (a 16-step size change over 192 characters: the plan fell from 1.1 MB to about 33 KB). The plan's `next_call` uses `expected_before_sha256` and `confirmed_after_sha256`; the full `expected_before` and `confirmed_after` are still accepted. The referenced snapshots live only in server memory, so after a server restart, for example, such an apply is refused with nothing written: plan again. Check values with the read tools. **Result shape changed**
- The JSON in every tool's `content` is no longer pretty-printed (`structuredContent` is unchanged)
- `illustrator_set_text_orientation`: snapshots carry `runs` of equal attributes instead of per-character `characters`. Comparison, verification and the inverse still cover every character. **Result shape changed:** result schema version 3
- `illustrator_set_text_style` and the text style steps of `illustrator_mutate_batch` no longer require new-document defaults when changing size, tracking, scales, fill or font of one-line point text (directly on a layer or in a plain group). Language, kinsoku, mojikumi, the auto-leading amount, paragraph spacing, kerning and other attributes are recorded before and compared after; a collateral change is reverted and named. Sizes that need more than five decimals are refused in the plan. 24 checks passed live on 30.8.2
- `illustrator_preflight_print`, `illustrator_preflight_images` and `illustrator_check_text_consistency` return a fixed `scopeNote` in every result: only the reported checks were run, no findings is not approval to submit, and the user confirms the final appearance in Illustrator and against the print vendor's requirements
- `illustrator_export` also writes artboards whose edges or size carry an unmeasured fraction of a point: the size is predicted from the size rounded to whole points times the scale, the plan lists the fractional edges in `edgeWarnings` and the accepted range in `expectedRange`, and the result returns the real size
- `illustrator_optimize_images`: when it stops at the render comparison, the before, after and difference images and a summary are kept in `evidenceDirectory` (bounded). They contain your artwork; delete them by hand when no longer needed. Nothing is kept on success
- Error reporting: when Illustrator throws during an apply, the failure message and the execution record keep the API name when known and the original text with paths and file names removed (up to 500 characters), instead of only `Apply failed.`. A failed result check is returned as one sentence naming the condition, the artboard and the values instead of a list of issues
- `illustrator_get_object` merges consecutive style runs with equal attributes and returns at most 32

#### Fixed

- A fractional bleed in `illustrator_export_pdf` (such as 8.5 pt) passed the plan, then stopped at the apply's verification, leaving a work copy and a staged PDF. A side that is not whole points is now refused in the plan with `bleed_invalid` and the nearest whole-point choices with their mm (for example 8 pt (2.82 mm) or 9 pt (3.18 mm)); nothing is rounded silently
- Documents whose artboard edges carry float noise (such as `5.7e-14` or `699.9999999999999`) stopped `illustrator_export`, `illustrator_update_artboard`, `illustrator_export_pdf`, `illustrator_export_outlined`, `illustrator_optimize_images` and `illustrator_create_trim_marks`. Values within 1e-6 are now compared as equal, and the document is never rewritten to fix the noise. Objects on such an edge count as inside the artboard for `illustrator_capture_preview`, `illustrator_preflight_print` and `illustrator_list_objects`
- With Japanese document or folder names, differences in how Node.js and Illustrator spell a path (composed or decomposed voiced marks, for example) could make backups, saves, export cleanup, save-as recovery, edit sessions and image path checks after placing or relinking fail
- Opening an already open file under a differently spelled path made Illustrator add an unusable second document. `illustrator_open_document` and the save-as switch now refuse before Illustrator opens it (save-as stops with `output_already_open`, resolved with `illustrator_reconcile_save_as`)
- `illustrator_create_layer` and `illustrator_reorder_layer` hit an Illustrator error during the apply when the neighboring layer that sets the position was locked or hidden. The plan now stops with `reference_sibling_locked_or_hidden` (nothing is unlocked for you)
- Text changes on long text or in large groups could pass the plan, then exceed the execution record limit at the apply and become indeterminate with the lock held. `illustrator_replace_text_range`, `illustrator_set_text_style`, `illustrator_replace_point_text`, `illustrator_replace_point_text_batch`, `illustrator_set_text_orientation`, `illustrator_set_no_break` and `illustrator_mutate_batch` now estimate the result size (counting surrogate characters such as emoji and the child lists of enclosing groups) and stop in the plan with `result_too_large` above 209,715 bytes
- `illustrator_get_object` could fail with only `No such element` on point or area text. The last paragraph of empty text or of text ending in a line break is returned as `trailing_empty_paragraph`, other unreadable values are kept in `details.unreadable` (attribute, Illustrator error number, next steps), and the readable values are returned. `illustrator_extract_design_tokens` and `illustrator_check_text_consistency` list unreadable frames in `unreadableTextFrames`
- Planning `illustrator_delete_objects` on a saved document with unsaved changes was rejected by the server's own check because the blocker message was too long. It now returns a plan blocked with `document_not_saved` and next steps (the full text is in `document.mutationBlockedReason`)
- After a compound path was changed in an edit session, saving was refused as an outside edit
- In beta.5, Adobe Fonts that Creative Cloud activates only for Adobe applications could not be confirmed, so font writes refused them. Calling `illustrator_list_documents` or `illustrator_find_fonts` once after starting Illustrator and before opening a document now reads Illustrator's own font list, and fonts in it count as confirmed for `illustrator_set_text_style` and `illustrator_replace_font` (stable Illustrator 30.8.2, foreground, unlocked). Each write also checks that Illustrator still finds the name. The list is kept in server memory only

#### Known limitations

- Adobe Fonts can be written only when they are in the font list read before any document was opened. After a server or Illustrator restart, and for fonts added after the list was read, read it again with every document closed. Using Adobe Fonts with `illustrator_replace_font` has not been checked live. Text creation and the character style tools still check fonts inside Illustrator only
- `illustrator_replace_text_range` and `illustrator_set_text_style` stop with `result_too_large` when one frame exceeds about 200 characters with short font information (about 180 with returns or forced line breaks), because of the size of the execution record. Split the range or the frame
- The decode checks of `illustrator_create_barcode` and `illustrator_create_qr_code` need zbarimg, which is not bundled; without it the check is `not_run`. Geometry and decode checks are not GS1 certification or a guarantee of scanning in print, and barcode placement on the case is not checked. Check the code under your final print conditions (method, paper, ink, reader)
- `illustrator_set_stroke_style` supports only the one measured shape: an open three-point straight path in a never-saved, one-layer CMYK document
- `illustrator_replace_area_text_range` is checked only on Illustrator 30.8.2 with one justified paragraph whose last line is aligned left
- `illustrator_render_artboards` does not bring Illustrator to the front. Bringing Illustrator to the front in `illustrator_capture_preview` and `illustrator_extract_text` is not done while the screen is locked and is not supported for a minimized Illustrator or one on another desktop (Space)
- In edit sessions above 3,000 objects, an outside attribute change made after its scan and before the save can be missed. Opening and saving take several minutes or more
- Changes continued as `dirty_file` do not detect changes outside the named targets
- Changes an AI app makes with its own script after a `custom_script` refusal are outside this server's plan, apply and read-back checks. Check the result with the read tools
- Changes on unchecked versions are checked by the before/after comparison, but have no live check on that version
- The layer-state steps of `illustrator_mutate_batch` and the tracking and scale text style steps have not yet been checked live through the published tools
- `pdfx` in `illustrator_export_pdf` checks only that PDF/X information was written. Conformance is not validated
- The short-line rules of `illustrator_audit_typography` are heuristic, and loose lines are not judged because the values to judge them were not measured. The rules with which it finds prohibited line breaks are verified by automated tests; live checks covered only that documents with Hard kinsoku get zero line-start and line-end findings. Ruby, warichu and forced line breaks are not judged
- `illustrator_create_trim_marks` has no Japanese or Roman default dimensions. Give every dimension
- `illustrator_optimize_images` can stop at render verification on large images (800×800 pt at the origin)
- `illustrator_replace_font` does not support composite fonts. In a saved document, each chunk needs a backup and a save. If the replacement font lacks the glyphs, verification fails and the change is reverted
- Moving text frames directly on a layer has not been checked on CMYK documents
- In `illustrator_mutate_batch`, the appearance, text-replacement and text-style steps do not return `next_steps` when they stop at a locked or hidden parent group (nothing is written)
- Writing the `illustrator_run_m6_appearance_preview_recipe` preview to a sync folder such as iCloud can be refused as changed even when the contents are the same. Write it outside sync folders
- Appearance at creation does not support spot colors or gradients. Use `illustrator_set_path_appearance` after creating
- Exporting a 4000×3000 px JPEG temporarily used about 570 MiB of Node.js memory to check its size (one measurement)
- Streamable HTTP is limited to automated tests and client connection checks. There is no record of operating Illustrator over HTTP
- In CMYK documents, compound path creation is not supported
- Group reads have a known intermittent issue where the target cannot be referenced. The cause is unresolved. When it happens, the operation stops on the safe side (fail closed), and results that cannot be confirmed are treated as indeterminate
- Execution records with long document identity information may not be readable back
- Existing stroked text cannot be edited
- Windows support is still in preparation; the published package is Mac only
- The Desktop extension is not signed. Check the author and version in the install dialog
- Always include `@beta` with npm. An install without a tag uses `latest`, which may not be this version
